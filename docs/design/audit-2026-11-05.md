# UX/UI audit, 5 November 2026

Scope: the `lo0` binary built from this checkout (`3d7ccc0-dirty`), run against this machine's real data (M5 Pro, 64 GiB, Ollama 0.34.4, 444 Claude Code and 39 Codex sessions). Every CLI command was run, including error paths and an empty `--claude-dir`. The TUI was driven in a pseudo-terminal at 120×36 and 80×24 through every screen, the palette, help, filter, search, the Keep plan and a Try run. The website is out of scope.

Measured against the brief: a hub for moving from Claude and Codex to local models and harnesses, that shows useful information, is easy to understand, works as expected, has charm and spacing, and has wow factor.

## Verdict

The bones are good. The information is unusually honest and specific: speed measured against your own Opus 5.5 replies, "62% of your sessions but only 11% of their API value", a plan view that shows every env var before it runs. The palette is restrained, alignment is careful, nothing goes past 80 columns in the CLI, and Models is a genuinely strong screen.

It falls short of the brief in three ways.

1. **It is a Claude Code tool with Codex bolted on, not a hub.** Codex sessions are counted, but Codex is never a setup to read, a harness to move to, or a name in the headings. A Codex user is told what carries over to Claude Code.
2. **The same fact is stated with different numbers on different screens.** For a tool whose value is trust in its numbers, this is the most damaging problem.
3. **The wow moment is buried.** Home is half empty at 120×36. The readiness score, the context histogram and the cost story live four pages down the fifth tab.

## P1: not yet a hub

The brief names Claude and Codex as the starting points. Today:

- `lo0 -h` says "lo0 checks whether your Claude Code work can run on a local model". The tab is "Your Claude", the Home column "YOUR CLAUDE", the screen title "How much of your Claude Code work can run locally?", the cost section "What your Claude Code use is worth".
- There is a "Claude Code setup" section but no Codex one. `~/.codex/config.toml`, its MCP servers, profiles and AGENTS.md files are not inventoried, so nothing about a Codex setup can be carried over.
- Codex is not a target harness, although it runs against local providers. The Harnesses screen offers Claude Code and OpenCode.
- With an empty `--claude-dir`, the verdict comes entirely from Codex sessions and then talks about carrying the setup over to Claude Code.
- Tool lists mix harness vocabularies: `Bash 36,123 · ... · exec_command 3,062`. Raw identifiers leak: `codex_work_desktop 2`.
- There is `--claude-dir` but no `--codex-dir`.

What a hub needs:

1. **Rename the history tab to "Your work"** with a `Claude Code · Codex · All` switch at the top, the same control as the Models filter. Every number on it says which it covers.
2. **Read the Codex setup** in `internal/codex` the way `claudecode` reads Claude's, and add Codex as a target under `internal/harness/codex`. AGENTS.md already allows exactly this.
3. **Harnesses lists every harness, installed or not**, each with its version, what carries over and an install action, the same as runtimes. LM Studio and llama.cpp "not installed" should likewise offer to install.
4. **Normalise tool names across harnesses** (`exec_command` → shell) in `usage`, and map client identifiers to display names.
5. **Cost covers both plans.** Codex usage against a ChatGPT plan is the other half of "what your use is worth".

## P1: flow and ease of use

**Home**
- At 120×36, 17 of 36 rows are blank. The strongest finding lo0 makes, how much of your work runs here and at what cost in time, is on tab 5.
- The action rows have no shortcut keys. [hub.md](docs/design/hub.md) designed `t k c x` against each row; they are worth adding back.
- `last try: Qwen3.6-35B-A3B, 5…` truncates the one fact in that cell that changes.

**Models**
- The YOUR SESSIONS column reads 65% for 9 of the top 10. It does not tell models apart, yet it takes the widest column.
- "best for you" puts Qwen3-Coder-30B-A3B (13 tok/s, very slow) third, above Gemma-4 and Nemotron-Lightning, which are 2 to 4 times faster with the same fit.
- The pace column mixes "3.2× slower" and "very slow". hub.md says very slow should still show the multiple.
- Search is scoped to the current filter: `/glm` under Installed says "No models match" though GLM-4.7-Flash is in Fits. Search everything and say which filter each hit is in.
- Compare: "Installed" mixes `✓ lo0/qwen3.6-35b-a3b:…` with `no`; "Quality kept" is identical in most columns. Show only rows that differ, or dim the equal ones.

**Harnesses**
- The detail lists all 34 instruction files, one per line, each "works as is". The useful part, what is lost or partly works, is off screen. Group what carries over into a count and lead with the exceptions.
- `~/.claude/CLAUDE.md` appears twice with identical text.
- The sub-row `claude        Claude` under "Claude Code on a local model" is unreadable without knowing it means "the `claude` command currently goes to Anthropic".

**Your Claude**
- Four pages mix the verdict, two charts, cost and the full scan inventory, ending in the "Claude Code setup" block that belongs on Harnesses. The verdict text repeats the Home step nearly word for word.
- Pressing `6` does nothing and says nothing.

**Palette and help**
- Every model row says "fits 65% of sessions". Show the line that differs: speed, memory, installed.
- The description column does not align ("Home   Your local AI setup" against "Harnesses   Where do you work…").
- It offers two actions (compare, save). Try, keep, benchmark, remove, undo and rescan should all be reachable from `ctrl+k`.
- Help lists `tab next screen` twice.

**CLI**
- Flag help is Go's default: single dashes (`-claude-dir`) under a usage line written with double dashes, and placeholders that read like defaults (`-harness claude-code`). Write the flag help by hand, as the command list already is.
- `try --harness` and `migrate --to` name the same thing differently. Pick one and accept both for a release.
- `flag provided but not defined: -foo` is passed through raw.
- `try --model nope` says it "does not fit this machine with a useful context window, or is not in the catalogue". lo0 knows which. Say which, and suggest the nearest IDs.
- Suggested commands wrap mid-command (`lo0 migrate` / `--to claude-code ...`), so they cannot be copied. Put commands on their own line, never wrapped.
- Plans have no summary line. Put "Downloads 1.9 GiB · writes 1 file · about 2 minutes" above the steps.

## P2: visual design

- **Contrast.** The faint grey `#5C6068` carries real content, such as "no local setup kept", footer hints and column subtitles: 247 cells on Home. It is about 3:1 on black and under 3:1 on a grey terminal background, against 4.5:1 for body text. Keep faint for rules and separators; move text to muted.
- **No focal point.** The accent appears on 42 cells of Home. Everything else is equal-weight grey, so the eye has nowhere to land. One large, accented figure per screen would fix that.
- **Context histogram.** On Your Claude it is half a screen of bars with no y-axis, a 256k marker only on the axis, and a peak spike that flattens everything else. Draw the window as a vertical rule through the bars, colour bars left of it good and right of it warn, and label the two sides ("65% fit · 35% would compact"). Use a log or capped y-scale.
- **Model card sparkline** has the same problem in miniature: the marker sits under the line, not on it.
- **Truncated identities.** Ollama tags (`qwen3-coder-30b-…`, `Satyr-V0.1-4B:Q4…`) are cut where the duplicates differ. Truncate in the middle so the tag stays visible.

## Wow factor

The data for each of these already exists in the assessment, so they are layout work, not new analysis.

1. **Home opens on the answer.** Replace the blank lower half with one line in large type and a split bar:

   ```
   65% of your work can run on this Mac today
   ██████████████████████████████████▌░░░░░░░░░░░░░░░░░░░  314 sessions fit · 169 would compact

   A typical reply   Opus 5.5         ██▌             6s
                     Qwen3.6-35B-A3B  ████████       20s   measured here
   ```

   The reply race is the number people feel; hub.md says so, and Home does not show it yet.

2. **Draw the setup.** On Home, show where each command goes now, so the hub idea is visible at a glance:

   ```
   claude        ──▶  Anthropic API          Opus 5.5
   codex         ──▶  OpenAI API             GPT-5.5
   claude-local  ──▶  Ollama  ──▶  Qwen3.6-35B-A3B   kept 5 Nov
   ```

3. **A live scan.** The scan takes 1.5 s. Show the machine line at once, then let session, token and dollar counts tick up as the history is read. It costs nothing and makes the first second feel alive.

4. **Benchmark as a race.** When `benchmark` runs, fill the Against bars live, local model against your measured Opus and GPT replies. This is the one place animation earns its place.

5. **The try report as the payoff.** After a Try, the session report is the most persuasive screen lo0 has: real tokens per second, real tool failures, against your history. Give it the same hero treatment as Home and make "Keep this setup" the obvious next key.

## Quick wins

Each of these is under an hour:

- One coverage number everywhere; remove "N in 10" ([home.go:261](internal/ui/tui/home.go:261)).
- Session span, not cost span ([home.go:254](internal/ui/tui/home.go:254)).
- Wrap warnings and the By hand lead line instead of truncating them.
- Deduplicate undo steps and instruction rows.
- Reserve the ✓ column on Models at 80 columns.
- Remove the duplicate `tab` line in help; align the palette description column.
- Never wrap a suggested command.
- Update the README's keys, Home description and Privacy section.
